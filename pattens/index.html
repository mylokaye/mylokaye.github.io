Pattens

A privacy-focused browser toolkit for generating campaign assets, validating email data, producing Dynamics FetchXML, simulating proposals, and creating polished browser mockups.

Built with

  • Next.js and TypeScript
  • Tailwind CSS and shadcn/ui
  • Static browser application
  • Small worker for selected hosted services
Use Pattens View Pattens on GitHub

One workspace for repeatable campaign tasks

Pattens brings small campaign-operations tools into one responsive interface. The aim is to reduce spreadsheet hand-offs and one-off browser utilities while keeping the limits of every output visible.

Generate

Create campaign URLs, consistent campaign names, and survey URLs. Generated assets remain visible in the workspace so they can be reviewed before use rather than being treated as an automatic publication step.

Validate

Check email syntax, duplicates, and domain MX availability, then export the reviewed results as CSV. Hosted MX validation sends only the domain to the resolver; it does not send the full email address. An MX record indicates whether a domain accepts mail, not whether an individual mailbox exists.

Logic

Generate Dynamics FetchXML from validated country or state lists. Ambiguous state names are flagged and blocked from generation so the tool does not silently choose a potentially incorrect region.

Simulation

Test a proposal against a defined audience panel and review a simulated debate, key concerns, and recommended next step. The supplied proposal, selected audience, duration, and fixed persona panel are sent to DeepSeek through a protected worker. The server-side API key is not exposed to the browser.

Simulation output is a scenario exercise based on the proposal supplied to it. It is not observed audience research, a forecast, or evidence that real customers will behave in the same way.

Studio

Turn screenshots into browser mockups using a local WebGL canvas, camera controls, colour gradients, and PNG export. This provides a repeatable way to prepare campaign or product visuals without sending the screenshot to a separate rendering service.

Privacy model

Most processing stays in the browser. The hosted worker is used only where the browser cannot safely or reliably perform the operation, including DNS resolution, validated URL checks, configured news sources, release monitoring, and proposal simulation.

  • Email addresses are not sent during MX validation; only their domains are resolved.
  • Public URL checks are restricted to validated targets.
  • Simulation credentials remain server-side.
  • Simulation results should be reviewed as generated scenarios, not factual audience evidence.

Who it is for

Pattens is designed for CRM, marketing-operations, campaign, and email specialists who need focused utilities but still want to understand what each tool processes, what it sends, and what must be manually reviewed.
